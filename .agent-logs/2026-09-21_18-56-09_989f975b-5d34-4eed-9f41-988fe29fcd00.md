## How it works

`transcript_segments` carries both `meeting_id` and `speaker_id`, and nothing stopped those two from disagreeing. The fix is a **composite foreign key**: `(speaker_id, meeting_id)` must exist as an `(id, meeting_id)` pair on `meeting_participants`. Django has no composite-FK field, so it's `RunSQL`, backed by a new `UniqueConstraint(["id", "meeting"])` on `Participant` — redundant on its own, since `id` is already the PK, but a composite FK needs a unique key of matching shape to reference.

Two details make it safe rather than disruptive:

- **MATCH SIMPLE** (Postgres default) skips the check when any referencing column is NULL, so unattributed segments and unassigned action items still insert freely. That's the common case and stays cheap.
- **DEFERRABLE INITIALLY DEFERRED** defers the check to commit, matching how Django writes its own FKs, so ORM cascades that touch parent and child in one transaction aren't tripped by statement ordering.

Deletes stay `NO ACTION` — Django's collector handles `SET_NULL` and `CASCADE` itself.

**I applied the same constraint to `ActionItem.owner`.** It's the identical defect, and I introduced it two turns ago; leaving it would have fixed the invariant in one place while a fresh hole sat next to it. Say the word if you'd rather I drop that half.

I also added `clean()` to both models so forms and the admin show *"Speaker must be a participant in this meeting"* rather than an `IntegrityError`. That's a usability layer, not the guarantee — the guarantee is in the database.

## Design notes

**Scoping** — `Q(owner=user) | Q(participants__user=user)`, so you see meetings you own *or* attended. Someone else's meeting returns **404, not 403**, so the API doesn't leak which IDs exist.

**Filtering** — `status` and `platform`, plus `type` as an alias for `platform`, since there's no `type` field and "what kind of meeting was this" is what `platform` answers. An invalid value returns 400.

**Invalid UUID** — the route is `<uuid:pk>`, so a malformed ID fails URL matching and returns 404 without touching the database. Tested with `not-a-uuid`, `123`, a truncated UUID, and `' OR 1=1--`.

**Two Meeting shapes** — `MeetingListSerializer` (metadata + annotated counts) and `MeetingDetailSerializer` (related objects). The list endpoint never pulls participants or highlights per row.

**PATCH returns the full detail shape**, so the client doesn't re-fetch after a change.

One deliberate omission: `Highlight.text`/`segments` are excluded from the serializer. Each would fire its own transcript query per highlight — that belongs on a highlight detail endpoint.

## Three things the rewrite surfaced

**1. Deferred constraints don't fire inside a test transaction.** This is the one worth knowing. The cross-meeting FKs are `DEFERRABLE INITIALLY DEFERRED` — the same way Django writes its own FKs — so Postgres checks them at `COMMIT`. A test runs in a transaction that never commits, so the violation surfaced during *teardown* instead of at the offending statement, and `pytest.raises` saw nothing. The tests now call a `check_deferred_constraints()` helper (`SET CONSTRAINTS ALL IMMEDIATE`) inside a savepoint.

This has a production implication too: under a request-level transaction, a cross-meeting write fails at the end of the request, not at the line that caused it. That's the cost of deferring, and it's the right trade for cascade safety — but it's worth knowing when you read a stack trace.

## Design decisions worth naming

**The player is a clock, not a media element.** The backend stores transcripts and timings, not recordings — there's nothing to play. `PlayerProvider` runs a rAF loop advancing a millisecond counter at the current rate. Everything downstream (seek bar, active line, clip in/out points) reads that counter and behaves exactly as it would against `<audio>`. Swapping in real media means replacing the provider, not its consumers.

**The waveform is derived, not invented.** Each of 140 bars covers a slice of the meeting and is sized by how much of that slice was speech, weighted by transcriber confidence. Pauses read as troughs, dense exchanges as peaks. Every bar traces back to data the API returned — simulated, not fabricated. Nothing in any component is hardcoded.

**Transcript paging.** The API paginates at 25 with no page-size param, so a 34-segment meeting is two pages. `useInfiniteQuery` appends rather than replaces, with a "Load more (25 of 34)" button — earlier lines must stay put while more arrive.

**Tabs are in the query string** (`?tab=transcript`), so a tab is deep-linkable and survives reload without making each tab its own route.

**Auto-scroll is scoped.** The active line scrolls into view with `block: 'nearest'` inside the transcript's own box — moving the whole page under someone reading would be hostile.
